### 1. 오늘 배운 내용
- 객체 지향 프로그램이란 무엇인지, 클래스와 상속, 접근 제어자 등을 배움
- 검증 로직을 실행 클래스에서 수행하는 방식과 데이터 주체인 클래스 내부에서 수행하는 방식의 차이점

### 2. 핵심 정리 (내 언어로)
- 이번 과제에서 처음에는 step1 클래스에서 일일이 데이터를 검사했지만 lion 객체 스스로가 자신의 상태를 활인할 수 있게 함 -> 이렇게 하면 객체가 독립적인 존재가 되어 관리하기 편리해짐. 

- 객체지향- 공통적으로 가지고있는 특성을 구조화하는 것!
- 클래스 - 설계도 / 접근 제어자를 다르게 설정해 캡슐화 수준을 조절함
    Step1에서는 메서드 내에서 유효성을 검사하는 절차지향적 방식 구현
    Step2에서는 객체를 생성한 뒤 객체의 메서드를 호출해 결과를 받는 객체지향적 방식 구현
    Step3에서는 클래스를 다른 패키지에서 호출 -> 접근제어자에 따라 접근 가능한 범위가 다름을 확인
- 접근 제어자 
    public : 어디서든 접근 가능
    default : 동일 패키지 내에서만 접근 가능
    private : 클래스 내부에서만 접근 가능하도록 보호
- 메서드 - 기능(함수) -> 이번 과제에서는 객체가 생성된 후 필드 값들이 유효한지 스스로 검증 (vailidateState())

### 4. 느낀 점
- 이번 과제를 통해 객체지향에 대해 직접 코드를 작성해 보며 어떻게 작동하는지 알 수 있었다. 처음 코드를 작성할 때 lion 클래스 안에 왜 굳이 if 문을 넣어 판단하게 해야 하는지 번거롭다고 생각했는데 수정하고 보니 코드가 깔끔해지면서 객체지향의 필요성을 느낄 수 있었다. 특히 package2를 새로 생성하여 접근 제어자를 테스트했던 Step3 과정이 가장 인상 깊었다. private으로 보호된 필드에 외부 패키지가 접근하려 할 때 에러가 발생하는데, 캡슐화가 단순히 데이터를 숨기는 것이 아니라 프로그램의 안정성을 지키는 것임을 알 수 있었다.

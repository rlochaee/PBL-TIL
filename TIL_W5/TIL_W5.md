# 📘 Today I Learned

### 1. 오늘 배운 내용
- 5주차 강의에서는 프로그래밍의 기초이자 핵심인 자료구조(배열, 리스트)와 함수(메서드)의 개념을 중점적으로 학습했습니다. 데이터를 효율적으로 관리하기 위해 순차적으로 정보를 저장하는 배열의 특징과, 크기가 가변적으로 변할 수 있어 실무에서 자주 활용되는 리스트(ArrayList)의 차이점을 알 수 있었다. 또한, 반복되는 로직을 독립적인 단위로 분리하여 재사용성을 높이는 함수의 원리를 배웠습니다.

- 배열 (Array)
동일한 타입의 데이터를 연속된 메모리 공간에 저장하는 자료구조.
인덱스(Index)를 통한 빠른 데이터 접근이 가능하나, 선언 시 크기가 고정되어 변경이 불가능한 정적 특징을 가짐.

- 리스트 (List / ArrayList)
데이터의 저장 순서가 유지되며 중복 저장이 가능한 자료구조.
배열과 달리 데이터의 추가 및 삭제에 따라 크기가 동적으로 조절되는 가변적 특징을 가짐.

- 함수 (Function / Method)
특정 목적의 로직을 수행하도록 설계된 독립적인 코드 블록.
중복 코드를 제거하고 가독성을 높이며, 유지보수 시 수정 범위를 최소화하는 재사용성의 핵심 요소.

### 2. 핵심 정리 (내 언어로)
- 5주차 미션은 4주차에서 구현했던 멤버 관리 시스템의 기능을 유지하면서, 계층형 구조로 수정하는 것이 핵심이었다. Step1, Step 2에서 객체 간의 결합도를 낮추기 위해 의존성 주입(DI)을 해보았다. 특히 인터페이스를 활용하여 서비스 로직이 특정 저장소 구현체에 의존하지 않도록 만드는 ‘느슨한 결합’에 대해 알 수 있었다. 또한, 실제 저장소인 MemoryMemberRepository와 테스트용인 MockMemberRepository를 비교해 보며 다형성이 실제 설계에서 어떻게 활용되는지 알 수 있었다. 

- 4주차와의 차이: 저번 주는 기능이 돌아가는 것이 우선이었다면, 이번 주는 저장 방식이 바뀌어도(예: DB 도입) 코드를 수정하지 않고 부품만 갈아 끼울 수 있는 구조를 만드는 것이다.

- new 키워드를 통해 직접 객체를 생성하면 클래스끼리 꽉 묶여버리는 ‘강한 결합’이 발생하는데, 이를 해결하기 위해 생성자를 통해 외부에서 객체를 넣어주는 의존성 주입(DI)을 적용했고, 이것이 유지보수에 유리함을 알 수 있었다.

### 4. 느낀 점
-마지막으로 느낀 점 섹션입니다. 5주차 미션을 수행하며 마주했던 기술적 고민과 질문하셨던 내용들을 토대로, 학습의 성장이 잘 드러나도록 줄글 형식으로 정리해 드립니다.

4. 느낀 점
- 처음 미션을 시작했을 때 이미 4주차에 잘 돌아가던 코드를 왜 굳이 세 개의 클래스로 분리해야 하는지, 인터페이스가 왜 필요한지 의문이 들었다. 특히 클래스 내부에서 new를 써서 객체를 만드는 방식이 왜 '강한 결합'이라는 문제를 일으키는지 체감하기 어려웠다. 하지만 인텔리제이에서 패키지 에러를 해결하고, 직접 생성자를 통해 의존성을 주입(DI)해 보면서 설계의 중요성을 조금씩 이해할 수 있었다. 또한, MockMemberRepository를 활용해 가짜 데이터를 반환하게 설정했을 때 서비스 코드나 메인 로직을 수정하지 않아도, 프로그램의 동작이 완전히 바뀌는 것을 확인할 수 있었다. 단순히 배열이나 리스트 같은 자료구조를 사용하는 문법 공부를 넘어, "나중에 이 코드가 수정될 때 얼마나 편할까?"를 고민해볼 수 있었던 거 같다.

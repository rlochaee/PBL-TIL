### 1. 오늘 배운 내용
- 데이터베이스와 데이터 영속성
    7주차에 사용했던 ArrayList 방식은 실행이 종료되면 데이터가 완전히 증발하는 휘발성 구조
    -> 서비스의 안정성과 지속성을 위해 서버 상태와 무관하게 데이터를 안전하게 보존하는 데이터 영속성을 구현해야 함

    MySQL 연동:
     데이터를 정형화된 테이블 구조로 관리하고, 시스템이 멈추어도 데이터가 영구히 유지

- JPA란?
    JPA는 자바 진영의 표준 ORM(Object-Relational Mapping) 기술 명세
    자바의 '객체 지향'과 관계형 데이터베이스의 '테이블 데이터' 사이의 구조적 불일치가 존재하는데, JPA가 이 둘 사이를 중간에서 매핑하고 연결해 주는 역할을 함

    과거에는 데이터 조작을 위해 수많은 문자열 SQL문(INSERT, SELECT, UPDATE)을 자바 코드 안에 직접 작성해야 했지만 JPA는 개발자가 자바 객체를 다루듯 코드를 짜면, 필요한 SQL을 내부에서 알아서 실행해 줌

### 2. 핵심 정리 (내 언어로)
- @Entity (이 클래스는 테이블이야)
    자바한테 어떤 클래스가 진짜 MySQL 데이터베이스에 표(테이블)로 만들어지는 것이라고 알려주는 기능

- @Id + IDENTITY (번호표 자동 발급)
    @Id로 이 번호가 회원 고유 번호(키)라고 지정하고, IDENTITY를 붙여 MySQL 데이터베이스에게 새로운 사람이 저장될 때마다 순번(1, 2, 3...) 알아서 붙일 수 있게 함

- @Enumerated(EnumType.STRING)
    컴퓨터는 기본적으로 역할을 숫자로 기억하려고 함 (예: LION은 0번, STAFF는 1번)
    but 나중에 역할이 추가되면 숫자가 꼬일 수 있기 때문에 숫자 말고 DB에 'LION', 'STAFF'라는 문자열 글자 그대로 똑바로 저장할 수 있도록 강제함

- JpaRepository 상속
    원래 회원 저장, 삭제, 수정, 조회하는 코드를 자바로 작성해야하지만, JpaRepository를 상속받으면 스프링이 save()(저장), findById()(찾기), deleteById()(지우기) 같은 필수 기능들을 만들어 줌

- ddl-auto=create
    코드를 고치고 서버를 새로 켤 때마다, 기존에 연습용으로 만들어진 DB 테이블을 밀어버리고(DROP), 새로 고친 자바 코드를 기준으로 깨끗한 새 테이블을 다시 짜주는(CREATE) 기능

- 영속성 컨텍스트 & ID 발급 (JPA 비밀 주머니)
    자바에서 new Member()로 회원을 막 만들었을 때는 고유 번호(id)가 없는 빈 상태 -> 
    repository.save() 를 하면 JPA가  DB가 발급해 준 고유 번호를 자바 객체에 채워 다시 반환
    = 그래서 save()를 하고 나면 자동으로 id가 채워진 회원 객체를 쓸 수 있게 됨

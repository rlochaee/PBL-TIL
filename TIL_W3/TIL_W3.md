# TIL_W3

### 1. 오늘 배운 내용
- 추상 클래스와 인터페이스(interface)의 활용: 모든 구성원의 공통 내용을 담는 Person 추상 클래스와, 과제 제출이라는 특정 행동 정책을 정의하는 PostPolicy 인터페이스를 설계

- 상속을 통한 코드 재사용: 아기사자와 운영진 클래스가 부모 클래스를 상속받아 중복된 필드(이름, 전공 등)를 효율적으로 관리

- 다형성 적용: 부모 타입인 Person으로 자식 객체들을 다루며, 조건문 없이도 각 객체가 자신의 역할에 맞는 getPolicy()와 getDetails()를 실행하도록 구현

- 캡슐화: 부모 클래스의 필드를 private으로 선언하고, getter와 getBaseInfo() 메서드를 통해 데이터 접근 제어

### 2. 핵심 정리 
- 공통점은 부모 클래스로 묶고, 차이점은 자식 클래스에서 구현하여 코드의 중복을 제거했다. 역할은 인터페이스로 과제 제출 가능 여부처럼 언제든 바뀔 수 있는 '규칙'은 인터페이스로 분리(정책 분리)하여, 나중에 운영진도 제출 가능하게 정책이 바뀌더라도 Main 코드를 수정할 필요가 없는 유연한 구조를 만들 수 있었다. 또한, getPolicy().canSubmit()이라고 명령만 내리면 객체가 알아서 판단하게 하는 것이 객체지향의 핵심임을 배웠다. 2주차에는 하나의 Lion 클래스 안에서 모든 것을 처리하려다 보니 코드가 길어졌지만, 3주차에는 역할을 객체별로 분산시켜 각 객체별로 따로 관리할 수 있도록 만들었다.

### 4. 느낀 점
- 이번 PBL을 통해 추상 클래스와 인터페이스의 실질적인 차이를 알아보았다. Person처럼 "무엇인지"를 나타낼 때는 상속을, PostPolicy처럼 "무엇을 하는지"를 나타낼 때는 인터페이스를 사용하는 것을 알 수 있었다. 특히, 다형성을 활용해 Main 클래스에서 조건문을 사용하지 않아도 프로그램이 잘 실행되는 점이 새로웠다. 2주차 3주차 PBL을 통해 구조를 분리하는 것이 초기 설계에는 시간이 더 걸릴지라도 장기적으로는 훨씬 관리하기 쉬운 코드가 된다는 것을 배웠다. 객체에게 판단을 맡기는 구조가 왜 유연한 설계의 핵심인지 체감할 수 있었다!
